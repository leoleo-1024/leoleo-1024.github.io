# ぼかし・モザイク（写真ぼかし・モザイク PWA）

iPhone で撮った写真の一部に **ぼかし・モザイク・黒塗り・渦巻き・モーションブラー** をかけて保存できる Web アプリ（PWA）です。

- 写真は端末内だけで処理し、外部へ送信しません（アカウント不要・広告なし・解析なし・バックエンドなし）
- ホーム画面に追加すると全画面で起動、一度読み込めばオフラインでも使えます
- 公開URL（`master` に反映後）：`https://leoleo-1024.github.io/blur/`

## 使い方

1. 「写真を選択」で写真ライブラリ／ファイルから1枚選ぶ
2. 下段で **効果**（ぼかし／モザイク／黒塗り／渦巻き／モーション）と **加工方法**（ブラシ／四角／楕円／消しゴム／移動）を選ぶ
3. ブラシは1本指でなぞる。四角・楕円はドラッグで範囲を作り、中をドラッグで移動、白い丸（ハンドル）でサイズ変更 →「適用」
4. 2本指でピンチ拡大・移動（描画中に2本目の指が触れると、そのストロークは取り消されます）。右上の「◯×」で全体表示に戻る
5. 「比較」を長押しすると元の写真を表示
6. 「保存」→ 形式（JPEG／PNG）を選んで「書き出す」→「共有・写真に保存」（iOS 共有シートの「画像を保存」で写真アプリへ）または「ダウンロード」。書き出した画像を長押しして保存することもできます

| 効果 | 強さ（1〜10） | 固有設定 | 備考 |
| --- | --- | --- | --- |
| ぼかし | ぼかし半径 | – | ガウスぼかし。画像の端で黒縁・透明にならない |
| モザイク | ブロックの大きさ | – | 格子は元画像の原点に固定（範囲が分かれても格子がずれない） |
| 黒塗り | なし | – | RGB(0,0,0) の不透明な黒。境界に半透明の元画素を残さない |
| 渦巻き | 中心の回転角（40°〜400°） | 時計回り／反時計回り | 範囲選択は中心・大きさから、ブラシはなぞった位置に連続した渦 |
| モーションブラー | ブラー距離 | 角度 0〜359°（0°=水平、90°=垂直） | 軸の両方向に対称 |

> 文字や個人情報を **確実に隠す** には「黒塗り」を使ってください。ぼかし・モザイク・渦巻き・モーションブラーは完全な秘匿手段ではありません。

## 開発

Node.js 20 以上（動作確認は Node 22）。

```bash
cd blur-app
npm install
npm run dev        # http://localhost:5173/blur/（--host 付きで同一LANの iPhone からも開ける）
```

```bash
npm run typecheck  # TypeScript 型チェック
npm test           # Vitest（画像処理エンジン・エンコーダーのユニットテスト）
npm run test:e2e   # Playwright（ビルドして起動し、Chromium の iPhone 15 Pro エミュレーション＋PCで操作テスト）
npm run build      # 型チェック → リポジトリ直下の ../blur/ に出力
npm run icons      # public/favicon.svg から PWA アイコンを再生成
```

E2E は `VITE_E2E=1` 付きで `dist-e2e/`（Git 管理外）にビルドしたものを使い、テスト用の参照（`window.__app`）はそのビルドにだけ含まれます。既に起動済みのプレビューサーバーは再利用されるので、コード変更後は `CI=1 npm run test:e2e` で毎回ビルドし直してください。

## デプロイ

GitHub Pages（このリポジトリの `master` ブランチ直下を公開）で配信します。`npm run build` の出力 `/blur/` をコミットして `master` に反映すれば公開されます（`_config.yml` でソースの `blur-app/` は公開対象から除外）。配置先を変える場合は `APP_BASE=/path/ npm run build`。HTTPS 配信が必要です（Service Worker・共有機能）。

## 設計

```
src/
  engine/         画像処理（DOM 非依存の純粋な TypeScript。Vitest で検証）
    types.ts        操作（Op）・形状（Shape）・効果パラメーター
    params.ts       強さ → 元画像ピクセル単位のパラメーター
    mask.ts         形状 → マスク（被覆率）のラスタライズ
    effects/        gaussian / pixelate / motion / swirl（各効果を独立した関数で実装）
    renderer.ts     合成エンジン（任意のレベル・任意の矩形を計算、タイルキャッシュ）
    history.ts      Undo/Redo
    view.ts         表示座標 ↔ 元画像座標の変換（一元管理）
  codec/          ストリーミング JPEG / PNG エンコーダーと Worker
  editor/         EditorController（ジェスチャー・プレビュー描画・書き出し）、写真を開く流れ
  lib/            読み込み・書き出し・共有・PWA
  state/          UI 状態（小さな外部ストア）
  ui/             React コンポーネント
```

- **非破壊編集**：元画像は変更せず、操作（形状は元画像座標、効果・強さ・方向・角度）を順番に記録します。表示も書き出しも「元画像 + 操作列」から毎回同じ関数（`Renderer.render`）で計算するため、Undo/Redo で完全に同じ結果になり、プレビューと保存画像が一致します。
- **合成ルール**：画素ごとに古い順に `効果 → lerp(現在, 効果画像, マスク)`、`消しゴム → lerp(現在, 元画像, マスク)`。後から適用した効果が上に表示され、消しゴムは全ての効果を消して元画像に戻します（消した場所への再加工も可）。
- **黒塗りの安全性**：効果画像は元画像から計算しますが、黒塗りより後の効果は「黒塗り済み（消しゴム反映済み）の画像」から計算します。黒塗りの上からぼかし等を重ねても、隠した画素がにじみ出ません（ユニットテストで確認）。マスクは二値で、画素に少しでもかかれば完全に黒にします。
- **解像度**：読み込み時に元画像から 1/2 ずつの縮小ピラミッドを作り、編集画面は長辺 3000px 以下のレベルで表示、拡大時は表示範囲だけを細かいレベル（最大で元解像度）で計算して重ねます。効果の強さは元画像ピクセル単位で定義し、各レベルで換算するので見た目が揃います（大きなぼかしは縮小レベルで計算して拡大、結果は同じで高速）。
- **タイルキャッシュ**：マスク・基準画像・効果画像を 256px タイル単位で計算し、上限付き LRU（160MB）でキャッシュ。ストローク中は変化した範囲のタイルだけを再計算します。
- **書き出し**：元解像度を帯ごとに合成。iOS Safari の canvas 上限（約1,677万画素）以下は `canvas.toBlob`、超える場合（24MP・48MP の写真）は自前の JPEG（ベースライン 4:2:0）／PNG（CompressionStream）エンコーダーを Worker で使います。出力は加工済みの画素のみで、EXIF（位置情報）・編集履歴・元画像は含みません。JPEG 品質 0.92。透明部分は PNG で保持（JPEG では白に合成）。
- **向き**：iOS Safari / Chrome は `<img>` のデコード時に EXIF の向きを反映するので、それを前提に向き補正後のサイズで扱います。
- **メモリ**：読み込み・書き出しとも帯（約400万画素）単位で canvas を使い、すぐ解放。確保に失敗した場合や、画素が読めない場合（iOS のメモリ不足時の挙動）は「縮小して開く」を提案します。約5,000万画素を超える写真は開く前に縮小を確認します。
- **PWA**：Service Worker は静的ファイルだけをキャッシュし、写真は `blob:` URL でのみ扱うためキャッシュされません。編集中は新しいバージョンを適用しません。

## テストで確認していること

- ユニット（Vitest）：5種類の効果が範囲内だけを変える、黒塗りが完全な黒、タイル分割・部分描画と一括描画が完全一致、消しゴムで元画像に戻り再加工できる、黒塗りの上に重ねた効果で隠した画素が漏れない、Undo/Redo の再現、モザイク格子の固定・強さでブロックが大きくなる、渦巻きの方向・強さ、モーションブラーの角度（0°=水平、180°違いは同じ）・距離・端の処理、プレビューレベルと元解像度の一致、PNG の往復、JPEG の構造（EXIF なし）、ファイル名
- E2E（Chromium の iPhone 15 Pro エミュレーション、CDP で実際のタッチ・ピンチを送信）：写真の読み込み（縦長・横長・正方形、EXIF の向き、非対応形式のエラー）、5種類のブラシ（高速ストロークでも途切れない・範囲外は不変）、四角・楕円の作成・移動・サイズ変更・適用・キャンセル、適用前の強さ・方向・角度のプレビュー反映、効果ごとの設定保持、消しゴム・Undo/Redo、ピンチで誤描画しない・描画中の2本目の指で取り消し、移動モード、拡大中の加工位置の正確さと高解像度表示、比較の長押し、未保存の確認、JPEG/PNG 書き出しと編集結果の一致（PNG は完全一致）・黒塗りに元画素が残らない、PNG の透明度、canvas 上限超え（1,700万画素）の写真を元解像度で書き出し、共有のキャンセル・失敗・成功、メモリ不足時の縮小、PC のマウス・ホイール・キーボード、オフライン起動と写真がキャッシュされないこと

## 未検証（iPhone 実機での確認が必要）

E2E は Chromium によるエミュレーションで、iOS Safari（WebKit）実機の代わりにはなりません。以下は実機で確認していません。

- [ ] iOS Safari／ホーム画面追加型 PWA での動作、Safe Area の表示
- [ ] 写真ライブラリから選んだ HEIC の読み込み（iOS は通常 JPEG に変換して渡す）と EXIF の向き
- [ ] 12MP（4032×3024）・24MP（5712×4284）・48MP（8064×6048）の写真の読み込み・編集の速度とメモリ（48MP は元画像だけで約 260MB を使います）
- [ ] 48MP の書き出し時間（自前エンコーダー、数秒〜十数秒の見込み）
- [ ] 共有シートの「画像を保存」で写真アプリに保存できること
- [ ] オフラインでの起動・編集
- [ ] 色空間：iPhone の写真（Display P3）は sRGB に変換して扱うため、非常に鮮やかな色がわずかに変わる可能性があります

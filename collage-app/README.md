# 壁紙コラージュ（iPhone壁紙コラージュ Webアプリ）

iPhone内の写真を好きな枚数選び、タッチ操作でコラージュして、壁紙用の高解像度画像（標準：iPhone 15 Pro 1179 × 2556 px）として保存するWebアプリです。

- 写真は端末内だけで処理され、外部サーバーへ送信しません（アカウント不要・広告なし・解析なし）
- PWA対応（ホーム画面に追加すると全画面で起動、一度読み込めばオフラインでも編集可）
- 公開URL（GitHub Pages の `master` に反映後）：`https://leoleo-1024.github.io/collage/`

## 機能

| 区分 | 内容 |
| --- | --- |
| 画像追加 | 写真ライブラリ／ファイルから複数枚まとめて追加、編集中の追加、個別削除、同じ画像の複数配置（Blobは共有） |
| レイアウト | フリー（移動・拡大・回転・重ね合わせ）／グリッド（自動・行列・余白）／モザイク（候補4種・再生成・余白） |
| タッチ操作 | 1本指ドラッグで移動、2本指でピンチ拡大・回転、タップで選択、空白タップで選択解除、四隅ハンドルで拡大、回転ハンドル（0/90/180/270°にスナップ）、中心線へのスナップとガイド表示 |
| 画像編集 | 拡大縮小・回転・左右/上下反転・トリミング（比率選択＋表示範囲のドラッグ/ピンチ、非破壊）・角丸・不透明度・重なり順・複製・削除・位置ロック |
| 背景 | 単色（プリセット＋任意色）、グラデーション、背景画像（拡大・位置調整）、透明（PNG時） |
| サイズ | iPhone 15 Pro / 15 Pro Max / SE、9:16、9:19.5、任意サイズ（iOSのcanvas上限を検証） |
| プレビュー | ロック画面・ホーム画面・画像のみ、時計／ウィジェット／Dock のガイド表示ON/OFF（書き出しには含まれない） |
| 書き出し | 書き出し画面を開くと自動で書き出し（形式を変えると自動で書き出し直し）、PNG / JPEG、出力後に形式・サイズを検証、iOS共有シート（「画像を保存」）、ダウンロードへのフォールバック、長押し保存の案内 |
| プロジェクト | IndexedDBへ自動保存、複数プロジェクト管理、再編集、名前変更、削除、前回の編集を再開 |
| バックアップ | プロジェクトを1つの .zip ファイルに書き出し（ホームの「…」→「バックアップを書き出す」）、「バックアップから復元」で新しいプロジェクトとして復元 |
| 履歴 | Undo/Redo（最大50ステップ、1回のドラッグ／ピンチ／スライダー操作＝1ステップ） |

## 起動方法

Node.js 20 以上（動作確認は Node 22）。

```bash
cd collage-app
npm install
npm run dev        # http://localhost:5173/collage/ で起動（--host 付きなので同一LANの端末からもアクセス可）
```

## ビルド

```bash
npm run build      # 型チェック → リポジトリ直下の ../collage/ に出力
npm run preview    # ビルド結果を http://localhost:4173/collage/ で確認
```

ビルド結果（`/collage/`）はリポジトリにコミットして GitHub Pages でそのまま配信する構成です。配置先を変える場合は `APP_BASE=/path/ npm run build` で base パスを変更できます。

## テスト

```bash
npm run typecheck  # TypeScript 型チェック
npm test           # Vitest（レイアウト計算・座標変換・履歴・保存/復元などのユニットテスト）
npm run test:e2e   # Playwright（ビルドして起動し、Chromium の iPhone 15 Pro エミュレーション＋PCで操作テスト）
```

E2E テストは `VITE_E2E=1` 付きで `dist-e2e/`（Git 管理外）にビルドしたものを使います。テスト用の内部状態参照（`window.__editor` など）はこのビルドにだけ含まれ、公開用の `../collage/` には含まれません。

E2E テストで確認している内容：複数画像の追加、タッチでの移動・ピンチ拡大・回転、ハンドル操作、Undo/Redo、選択解除、削除・複製・反転・重なり順・背景色、グリッド/モザイクと表示範囲調整、EXIF の向き補正、1179×2556 PNG の書き出しと編集画面とのピクセル一致（UI非映り込み）、再読み込み後の再編集、プレビュー、HEIC非対応時のエラー表示、50枚の追加・編集・書き出し、PCのマウス/キーボード操作、オフライン起動。

> 注意：E2E は Chromium によるエミュレーションです。iOS Safari（WebKit）実機での確認の代わりにはなりません。

## iPhone 実機での確認方法

### 方法1：同じWi-Fi内でローカルサーバーに接続

```bash
cd collage-app
npm run dev
```

表示される `Network: http://192.168.x.x:5173/collage/` を iPhone の Safari で開きます。
※ `http://`（非HTTPS）では Service Worker（オフライン機能）と一部の共有機能が無効になる場合があります。保存・共有を確認するときは方法2を使ってください。

### 方法2：GitHub Pages（HTTPS）で確認

1. このブランチを `master` にマージ（`/collage/` のビルド済みファイルを含む）
2. iPhone の Safari で `https://leoleo-1024.github.io/collage/` を開く
3. 共有ボタン →「ホーム画面に追加」でアプリとして起動

### 実機チェックリスト

- [ ] 写真ライブラリから複数枚選べる（HEICが自動でJPEGに変換されて読み込まれる）
- [ ] 1本指で移動、2本指でピンチ・回転でき、ページ全体がスクロール・拡大しない
- [ ] 書き出し →「写真に保存・共有」→「画像を保存」で写真アプリに保存できる
- [ ] 保存した画像を「壁紙に設定」して、プレビューと見え方が大きく変わらない
- [ ] アプリを終了・再起動してもプロジェクトが残っている

## 技術構成

- React 19 + TypeScript + Vite 8、Tailwind CSS 4（UI部品は自作の軽量コンポーネント）
- Konva + react-konva（編集画面の描画とハンドル）
- Zustand（編集状態・履歴）、Dexie（IndexedDB）
- vite-plugin-pwa（Service Worker・マニフェスト）
- Vitest + Playwright

```
src/
  model/      編集データモデル（描画ライブラリに非依存の純粋なTypeScript）
    types.ts      Project / ImageAsset / ImageLayer などの型
    geometry.ts   切り抜き(cover)・パン・ピンチ・当たり判定などの計算
    layout.ts     グリッド／モザイク／初期配置
    presets.ts    壁紙サイズのプリセット（機種追加はここに追記）
  render/     Canvas 2D による描画エンジン（書き出し・サムネイル・プレビュー）
  storage/    IndexedDB（Dexie）
  state/      Zustand ストア（Undo/Redo・自動保存・画像キャッシュ）
  components/ CanvasStage（Konva・ジェスチャー）と共通UI
  screens/    ホーム／画像選択／編集／プレビュー／書き出し／設定
```

### 設計上のポイント

- **データモデルと描画の分離**：編集状態は `model/types.ts` の純粋なデータで、座標はすべてキャンバス（出力ピクセル）基準。画面サイズに依存しません。書き出しは Konva を使わず `render/renderProject.ts`（Canvas 2D）でデータから直接描画するため、将来ネイティブアプリ（SwiftUI / Capacitor 等）へ移行してもモデルと描画規則をそのまま移植できます。
- **編集画面との一致**：編集画面（Konva）と書き出し（Canvas 2D）は同じ規則（中心基準・回転→反転→角丸クリップ→正規化cropで描画）で実装し、E2Eテストでピクセル比較しています（平均差 約0.4/255）。
- **非破壊トリミング**：元画像は保持したまま、`fit`（拡大率・表示中心）から `crop`（正規化座標）を算出します。
- **メモリ対策**：取り込み時に 編集用プレビュー（長辺1024px）・サムネイル（240px）を生成し、編集画面はプレビューのみ使用。書き出し時だけ高解像度画像を1枚ずつデコードして描画後すぐ解放します。取り込みは1枚ずつ処理し、間にUIへ処理を譲ります。
- **保存の直列化**：自動保存・画面離脱時の保存などが重なっても、保存は1件ずつ順番に実行し、常にその時点の最新内容を書き込みます（古い内容で上書きされない）。
- **アプリの更新**：新しいバージョンを配信しても編集中には再読み込みせず、ホーム画面に戻ったとき（保存完了後）か次回起動時に適用します。
- **縮小時の画質**：大きく縮小して描画する場合（書き出し時の小さな画像・回転画像、プレビュー生成）は 1/2 ずつ段階的に縮小してジャギーやモアレを抑えます。一時的に使う canvas は最大でも切り抜き範囲の 1/4 程度の面積で、描画後すぐ解放します。
- **画像の向き**：iOS Safari / Chrome は `<img>` のデコード時に EXIF の向きを反映するため、それを前提に向き補正後のサイズで扱います。

## バックアップファイルの形式

`collage-backup-<名前>-<日時>.zip`（無圧縮 ZIP）。中身は次のとおりです。

```
manifest.json                 形式（wallpaper-collage-project / formatVersion 1）、プロジェクトの編集データ、画像一覧
assets/<id>/original.<ext>    書き出しに使う元画像
assets/<id>/preview.<ext>     編集画面用の縮小画像
assets/<id>/thumb.<ext>       一覧用サムネイル
thumbnail.jpg                 ホーム画面用サムネイル（ある場合）
```

- 書き出しは画像を1つの大きなバッファにコピーせず連結するため、画像が多くてもメモリを使いすぎません。
- 復元時はプロジェクトと画像に新しいIDを振るため、既存のプロジェクトは上書きされません（同じファイルを2回読み込むと2つになります）。
- 復元は画像を1枚ずつ保存し、途中で失敗した場合は保存した画像を取り消します。各ファイルはCRCで破損を検査し、壊れた画像だけを除いて復元します。
- PCで解凍・再圧縮した（DEFLATE）ZIP も読み込めます（`DecompressionStream` 対応ブラウザ）。

## 技術的制約と代替策

| 制約 | 対応 |
| --- | --- |
| iOS の Web アプリは写真ライブラリへ直接書き込めない | Web Share API で共有シートを開き「画像を保存」を選んでもらう。非対応環境はダウンロード、さらに画像の長押し保存を案内 |
| 共有シートはタップ直後にしか開けない（非同期処理を挟むと失敗する） | 「書き出す」と「写真に保存・共有」を2段階に分け、書き出し済みファイルを即座に共有 |
| HEIC は Safari 以外のブラウザで読めないことがある | iOS の写真選択では自動で JPEG に変換される。読めない場合は原因と対処法を表示 |
| iOS Safari の canvas 上限（約1,670万ピクセル） | 任意サイズは上限内に制限。元画像は長辺4096pxを超える場合のみ縮小して保持 |
| IndexedDB はブラウザデータ消去・長期間未使用・容量不足で消えることがある | 起動時に永続化を要求、容量不足時は警告。プロジェクトはバックアップファイル（.zip）に書き出して「ファイル」アプリ等に保存でき、いつでも復元可能 |
| iOS の壁紙設定時の拡大（視差効果）や時計の位置は端末・設定で変わる | プレビューのガイドは「目安」と明示 |

## 未検証・今後の課題

- **iPhone 実機（iOS Safari / WebKit）での動作は未検証**です。上記チェックリストでの確認をお願いします（特に共有シートでの保存、ピンチ操作、メモリ）。
